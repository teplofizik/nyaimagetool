# ISO9660

`NyaFs` supports ISO9660 CD images in both directions:

- **read**: primary volume descriptor, directories/files, Rock Ridge names/
  permissions/symlinks and Joliet names fallback;
- **write**: ISO9660 Level 1 names plus Rock Ridge metadata.

## Commands

Load is auto-detected:

```text
load image.iso
```

Write a loaded filesystem as ISO:

```text
store out.iso ramfs iso9660
```

or select the filesystem type first:

```text
set ramfs filesystem iso9660
store out.iso ramfs iso9660
```

## What is preserved

- Directory tree and file contents.
- Rock Ridge long names (NM), mode/uid/gid (PX), symlinks (SL), device nodes
  (PN).
- Reader also understands Joliet names when Rock Ridge is absent.
- Multi-extent files are combined when reading.

## Limitations

- The writer emits ISO9660 Level 1 identifiers plus Rock Ridge; it does not emit
  a Joliet tree. Windows Explorer without Rock Ridge may show 8.3 names.
- Very long Rock Ridge names are truncated to fit one directory record; `CE`
  continuation entries are not written yet.
- Multi-extent writing, boot records (El Torito), UDF and xattrs are not
  supported.
- ISO9660 has no hard links; symlinks are represented with Rock Ridge `SL`.

## Verification

- `genisoimage -R` / `-J` images load and export correctly.
- Generated images are readable by 7-Zip and `isoinfo`.
- A generated image can be mounted read-only in Linux and contains the expected
  files and symlinks.
