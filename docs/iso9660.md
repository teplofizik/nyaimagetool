# ISO9660

`NyaFs` supports ISO9660 CD images in both directions:

- **read**: primary volume descriptor, directories/files, Rock Ridge names/
  permissions/symlinks and Joliet names fallback;
- **write**: ISO9660 Level 1 names plus Rock Ridge metadata.

## Commands

Load is auto-detected:

```text
load image.iso
```

Write a loaded filesystem as ISO:

```text
store out.iso ramfs iso9660
```

or select the filesystem type first:

```text
set ramfs filesystem iso9660
store out.iso ramfs iso9660
```

## Bootable ISO (El Torito)

`build` can create an El Torito no-emulation boot record and catalog:

```yaml
schema: 1
format: iso9660
options: { boot-image: boot/loader.bin, boot-load-size: 8 }
content: { dir: inputs/cd_root }
```

- `boot-image` is a path inside the ISO tree (the file is included normally);
- `boot-load-size` is in 512-byte sectors (0/omitted = size of the boot file);
- `boot-load-segment`, `boot-media-type`, `boot-system-type`, `boot-identifier`
  control the catalog entry (media type 0 = no emulation; 1/2/3 = floppy,
  4 = hard disk).
- The boot record descriptor is at sector 17, followed by the catalog and the
  normal ISO path tables; the catalog validation checksum and the boot image LBA
  are generated automatically.

UDF images remain data-only: El Torito is an ISO9660 feature.

## What is preserved

- Directory tree and file contents.
- Rock Ridge long names (NM), mode/uid/gid (PX), symlinks (SL), device nodes
  (PN).
- Reader also understands Joliet names when Rock Ridge is absent.
- Multi-extent files are combined when reading.

## Limitations

- The writer emits ISO9660 Level 1 identifiers plus Rock Ridge; it does not emit
  a Joliet tree. Windows Explorer without Rock Ridge may show 8.3 names.
- Very long Rock Ridge names are truncated to fit one directory record; `CE`
  continuation entries are not written yet.
- Multi-extent writing and xattrs are not supported.
- El Torito is written by `build` (no-emulation and media type selection);
  loading an existing ISO does not expose the boot catalog/image as separate
  image elements yet.
- UDF is a separate filesystem; UDF boot is not implemented.
- ISO9660 has no hard links; symlinks are represented with Rock Ridge `SL`.

## Verification

- `genisoimage -R` / `-J` images load and export correctly.
- Generated images are readable by 7-Zip and `isoinfo`.
- A generated image can be mounted read-only in Linux and contains the expected
  files and symlinks.
